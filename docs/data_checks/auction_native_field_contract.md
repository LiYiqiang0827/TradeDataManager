# Auction snapshot field handling

The source contract is documented in [THS Fuyao `llms-full.txt`, auction snapshot section](https://fuyao.aicubes.cn/llms-full.txt) (API documentation lines 1829–1900). The supported request stages are `live` and `final`. The envelope `data.timestamp` is the response assembly time in Unix milliseconds; it is not the market event time. The collector retains this in the compatibility column `auction_timestamp` and records whether it came from the API or a local response-time fallback. `auction_request_stage` records the requested stage.

The provider exposes native fields including `auction_price`, `auction_pct`, `auction_volume`, `auction_amount`, `auction_unmatched`, `auction_turnover_pct`, `auction_yesterday_ratio_pct`, `auction_volume_ratio`, `pre_close_price`, `open_price`, `last_price`, `float_market_cap`, and `name`. The local schema now stores these native values in nullable columns. Numeric source fields are retained as `REAL`. The source documentation does not define the volume or amount units; the collector preserves source values and does not convert them.

`auction_price` is the auction price. `last_price` remains the latest quoted price and may differ. `auction_turnover_pct` is retained as its own field. The generic `volume` and `turnover` columns are not populated from auction-specific fields, and missing values remain NULL rather than zero.

Existing daily auction tables receive only additive nullable columns when the table is next ensured. Existing rows are not rewritten; historical values in the new columns remain NULL until separately recovered from a verified source. No historical value is inferred from a current `final` snapshot.
