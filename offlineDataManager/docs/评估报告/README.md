# 评估报告

代码质量审查、bug 分析、性能评估报告的归档目录。

## 文件命名约定

`YYYY-MM-DD_报告类型_简短描述.md`

例:
- `2026-09-16_代码审查_5个update_ctrl误推bug.md`
- `2026-09-16_一致性排查_文档vs代码.md`
- `2026-09-15_性能评估_30分钟首次全量.md`

## 报告类型

- **代码审查** — 主动/被动的代码 review,记录发现的 bug、坏味道、改进建议
- **一致性排查** — 文档和代码不一致的地方
- **性能评估** — 大数据量跑下来的耗时、瓶颈分析
- **架构评估** — 整体架构的合理性、改进空间
- **业务评估** — A 股数据覆盖度、数据质量

## 写法建议

每个报告应该:
1. **结论先行**:一段话总结"发现了什么 / 修了什么"
2. **详细发现**:分类列出每个问题
3. **修复记录**:每个 bug 怎么定位、怎么修、改了哪些文件
4. **测试验证**:怎么确认修对了
5. **遗留问题**:还没修的、已知 limitation、改进建议
