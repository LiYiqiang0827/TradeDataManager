# 02 新增数据接入指南

> 本文是**"在 offlineDataManager 里加一种新数据"**的标准操作流程。
> 读完后应能:**明确知道加新表需要改哪些文件、按什么顺序、每改一处要同步更新哪些文档**。
>
> 适用于:加新的"业务数据源"(比如:港股行情、ETF 基金、龙虎榜、机构持仓等),**不是**"加新表存已有数据"(那只是改 schema,见 [01_数据详细设计文档.md](01_数据详细设计文档.md) 的 schema 部分)。

## 1. 总览:加一种新数据的 7 步流程

|---|---|---|---|---|

| 3 | 在 `offline_db_client.py` 加 `get_xxx` 只读接口 | `scripts/core/offline_db_client.py` | `代码详细设计/offline_db_client.md`(表格行 + 接口说明) | 中 |
| 4 | (可选) 在某个 `service_xxx.py` 加一个 service | `scripts/service/service_xxx.py` | `代码详细设计/service_xxx.md`(新建) | 中 |
| 5 | (可选) 在 `scheduler_updateData.py` 注册新 service | `scripts/scheduler/scheduler_updateData.py` | `代码详细设计/scheduler_updateData.md` + 同步 4 处顶层文档 | 中 |

## 2. 详细步骤(以"加港股日 K"为例)

### 步骤 1:`settings.py` 加 schema

**文件**:`scripts/config/settings.py`

**位置**:现有 3 个 schema 字符串之一(SCHEMA_SQL_BASIC / SCHEMA_SQL_KPL / SCHEMA_SQL_NEWS)。**新建独立 DB 还是放现有 DB? 决策标准**:

| 场景 | 放哪个 DB | 例子 |

### 步骤 2:`offline_downloader.py` 加 `update_xxx` 方法

**文件**:`scripts/core/offline_downloader.py`

**位置**:作为 `CNDataDown` 类的新方法,**建议加在类末尾**,跟其他 12 个 `update_*` 排在一起。

**模板**:

```python
def update_hk_day(self, start_date: str = None, end_date: str = None) -> int:
    """港股日 K 更新
    
    数据源:tushare pro.hk_daily(假设接口,实际可能有差异)
    写入:db_cn_basic.db:tbl_hk_day
    断点:tbl_basic_ctrl.cn_hk_day
    
    Args:
        start_date: YYYYMMDD,默认 None(走 ctrl.max_date 或 20150101)
        end_date: YYYYMMDD,默认 None(今天)
    """
    table = "tbl_hk_day"
    ctrl_key = "cn_hk_day"
    t0 = time.time()
    total_inserted = 0

    end_date = _fmt_yyyymmdd(end_date) if end_date else _fmt_yyyymmdd(datetime.now())
    if start_date:
        sd = _fmt_yyyymmdd(start_date)
    else:
        last = get_ctrl(self.conn_basic, ctrl_key)
        sd = last if last else "20150101"

    try:
        d_start = datetime.strptime(sd, "%Y%m%d")
        d_end = datetime.strptime(end_date, "%Y%m%d")
    except ValueError:
        logger.error(f"[港股日K] 日期格式错误: sd={sd} end={end_date}")
        return 0

    cur = d_start
    last_success_date = None
    while cur <= d_end:
        td = cur.strftime("%Y%m%d")
        try:
            df = self.client.hk_daily(trade_date=td, limit=6000, offset=0)  # 改这里
            if df is None or len(df) == 0:
                cur += timedelta(days=1)
                continue
            df["snap_ts"] = snap_ts()
            inserted = upsert_df(self.conn_basic, df, table,
                                key_cols=["ts_code", "trade_date"])
            if inserted > 0:
                last_success_date = td
            total_inserted += inserted
        except Exception as e:
            logger.error(f"[港股日K:{td}] 失败: {e}", exc_info=True)
        cur += timedelta(days=1)

    if last_success_date:
        update_ctrl(self.conn_basic, ctrl_key, last_success_date)
    elapsed = time.time() - t0
    logger.info(f"[完成] {table:<28} +{total_inserted:>12,} 行  耗时 {elapsed:.1f}s")
    return total_inserted
```

**关键点**:
- `self.client.hk_daily(...)` 需要在 `TushareClient` 里有这个方法(可能要先在 `~/TradingAgent/coreClient/tushare_client.py` 加)
- **单次拉不分页**(港股 < 3000 只/天,单次 limit=6000 足够)
- **空日不推进断点**(`if inserted > 0` 推进)
- **异常 catch 在循环内**,不中断后续日期

**要同步更新的文档**:
- `代码详细设计/offline_downloader.md` 表格加一行(参照 13 个 update_* 表格)

### 步骤 2.5:数据源对接实战(Tushare / 开盘啦 接入细节)

加新数据时,**最容易踩的坑不是写 Python,而是不知道目标接口的脾气**。本节汇总所有需要查清楚的事。

#### 1. Tushare 接口的"5 个必查项"

加新 tushare 接口前,**先去 Tushare 文档页查清 5 件事**:

| # | 查什么 | 怎么查 | 例子(`pro.daily` 日 K) |
|---|---|---|---|
| 1 | **接口名 + 完整 URL** | Tushare pro 文档 → 接口列表 | `https://tushare.pro/document/2?doc_id=27` |
| 2 | **必填参数 + 可选参数** | 同一页 | 必填:`ts_code` 或 `trade_date`;可选:`start_date` / `end_date` |
| 3 | **单次最大 limit** | 同一页 / 测试 | `limit=6000`(不是 5000,不是 10000) |
| 4 | **是否支持 offset 分页** | 同一页 / 测试 | 支持,`offset=0` / `6000` / `12000`... |
| 5 | **返回字段 + 字段类型** | 同一页 | `ts_code, trade_date, open, high, low, close, pre_close, change, pct_chg, vol, amount` |

**AI 接手时**,把 Tushare 文档 URL 写进代码注释,新 AI 一查就明白:

#### 2. limit + offset 循环抓取机制(标准模式)

**Tushare 几乎所有"按日期循环拉"接口都支持 limit + offset 分页**。标准模式:

```python
def update_with_pagination(self, start_date, end_date, ...):
    """所有按日循环的 update_* 都遵循这个模式"""
    cur = start_date
    while cur <= end_date:
        td = cur.strftime("%Y%m%d")
        offset = 0
        page_count = 0
        while True:  # 内层:某天的分页循环
            df = self.client.xxx(trade_date=td, limit=LIMIT, offset=offset)
            if df is None or len(df) == 0:
                break
            # ... 写入 + 推进 ...
            if len(df) < LIMIT:
                break  # 当天拉完(返回 < limit 表示最后一页)
            offset += LIMIT
            page_count += 1
            if page_count >= 50:  # 安全上限(30 万条)
                logger.warning(f"[xxx:{td}] 超过 50 页,停止")
                break
        cur += timedelta(days=1)
```

**关键参数**:
- **单次 limit**:5000/6000/8000(看接口,固定不变,写在 update_* 里)
- **页数上限**:**50 页**(30 万条,防止接口报错无限循环)
- **空数据早停**:`len(df) < LIMIT` 表示最后一页

**经验值**(Tushare pro 常用接口):

| 接口 | 单次 limit | 实际日均行数 | 是否需要分页 |
|---|---|---|---|
| `daily` | 6000 | ~5500(A 股,~887 只有数据) | **是**(2024+ 接近 6000) |
| `adj_factor` | 6000 | ~5500 | **是** |
| `kpl_list` | 8000 | < 100 | 否(只数 < 8000) |
| `kpl_concept_cons` | 3000 | 几百 | 否 |
| `news` | 1500 | 不定 | **是**(高频源可能 > 1500) |
| `hk_daily` | 6000(假设) | < 3000 | 否 |
| `fund_daily` | 6000(假设) | < 5000 | 看实际 |

**新加接口时**,**先空跑 1 天**看返回长度,再决定是否需要分页。

#### 3. 频率限制(已经在 coreClient 自动处理)

**Tushare pro 限制:200 次/分钟**(`TUSHARE_RATE_LIMIT_PER_MIN = 200`)
**开盘啦限制:30 次/分钟**(`KPL_RATE_LIMIT_PER_MIN = 30`)

**好消息**:`TushareClient` / `KPLClient` 在 `~/TradingAgent/coreClient/` **已经自动处理频率限制**:
- `RateLimiter` 类(滑动窗口 60 秒)
- 超限自动 `time.sleep(60 - 最早调用时间 + 0.1)` 等到下一分钟
- `@with_retry` 装饰器:网络失败自动重试 3 次(指数退避 2/4/6 秒)
- 日志 warning 打印 `触发限流,sleep {N}s`

**offline 写代码时不需要再关心频率限制**。但要**意识到**:

| 现象 | 原因 | 应对 |
|---|---|---|
| `update_xxx` 跑得比"理论时间"慢(每分钟 200 次封顶) | 触发限流,sleep 等待 | 正常,无需处理 |
| `update_xxx` 单次调用偶尔失败,日志有 `第 N/3 次失败` | 网络抖动,触发重试 | 正常,无需处理 |
| `update_xxx` **完全失败**(3 次重试后) | 持续网络问题 / token 过期 / 接口下线 | **必须查 log + 跑 `validate_data.py` 验证** |

**调频率限制常量**:`~/TradingAgent/coreClient/tushare_config.py` / `kpl_config.py`:
```python
TUSHARE_RATE_LIMIT_PER_MIN = 200  # Tushare 官方限制
TUSHARE_RETRY_MAX = 3            # 失败重试 3 次
TUSHARE_RETRY_SLEEP = 2          # 基础 sleep 2 秒(实际 2/4/6)
```

#### 3.5 如何选 tushare vs 同花顺 KPL(数据源选择决策)

**两类数据源的区别**:

| 数据源 | 平台 | 客户端 | 频率限制 | 数据延迟 | 适用场景 |
|---|---|---|---|---|---|
| **tushare** | [tushare.pro](https://tushare.pro) | `TushareClient` | 200 次/分钟 | **T+1 滞后**(第二天早上) | A 股 / 港股 / 美股 / 期货 / 公募基金 / 指数基础信息等标准数据 |
| **同花顺 KPL** | [同花顺 10jqka / iFinD / 长华 aphis.longhuvip.com](https://www.10jqka.com.cn) | `KPLClient`(私有 HTTP API) | 30 次/分钟 | **实时**(盘中可用,16:30+ 后数据完整) | 涨停实时盯盘 / 涨停表现详情 / 题材 / 异动实时推送等 |

**典型数据示例**:
- `tbl_cn_kpl_list`(涨停榜) → **tushare**(`pro.kpl_list`),T+1
- `tbl_cn_kpl_limit_performance`(涨停表现详情) → **同花顺 KPL**(`HisHomeDingPan/DailyLimitPerformance`),实时
- `tbl_cn_daily_basic`(每日指标) → **tushare**(`pro.daily_basic`),T+1
- `tbl_cn_index_basic`(指数基本信息) → **tushare**(`pro.index_basic`),静态

**选择决策**:
- 数据量大 + T+1 够用 → **tushare**(便宜,200/分钟)
- 盘中实时盯盘需要当日数据 → **同花顺 KPL**(实时接口)
- 没有 tushare 文档 / 接口 → **同花顺 KPL**

**同花顺 KPL 双接口策略**(2026-09-15 实现):
- 日期 == today → `KPLClient.fetch_realtime_limit_performance()`(实时 host apphwhq)
- 日期 < today → `KPLClient.get_daily_limit_performance(date_str)`(历史 host apphis)

#### 4. 实战踩坑清单(加新接口时必查)

| # | 坑 | 怎么避免 |
|---|---|---|
| 1 | **接口名写错**(`pro.daily` vs `pro.day`) | 加完后立即 `python3 -c "from coreClient.tushare_client import TushareClient; c=TushareClient(); print(c.daily.head())"` 测一下 |
| 2 | **limit 超过 tushare 单次上限**(报错 429 / "超过最大限制") | 先用 `limit=100` 试一次,看返回数据量,再选合适 limit |
| 3 | **日期格式不对**(YYYYMMDD vs YYYY-MM-DD) | 统一用 `YYYYMMDD`(本项目所有 `_fmt_yyyymmdd` 都归一到这里) |
| 4 | **返回 df 字段名跟 schema 不一致** | 查 tushare 文档,**字段名要跟 `settings.py` 的 `CREATE TABLE` 字段名完全一致**;不一致时在 `upsert_df` 里会被自动过滤掉,**数据丢失** |
| 5 | **返回空 df 但没报错** | `update_xxx` 内部要 `if df is None or len(df) == 0: continue`,**不推进断点** |
| 6 | **tushare token 失效** | 跑任何 service 前先 `validate_data.py` 测一个 date 看是否 401 |
| 7 | **接口已下线**(tushare 偶尔会下线冷门接口) | 看返回错误信息,搜 tushare 公告 |
| 8 | **pro 接口需要积分**(某些接口要 5000 积分) | 文档会标,看 `pro.xxx` 右上角"权限" |

#### 5. Tushare 文档查找流程(给 AI 用)

加新 tushare 接口,按这个流程查文档:

1. **打开** [https://tushare.pro/document/2](https://tushare.pro/document/2) (接口列表)
2. **搜索**新接口名(如 "hk_daily" / "fund_daily" / "dragon_tv")
3. **打开对应 doc_id 链接**(URL 形如 `tushare.pro/document/2?doc_id=27`)
4. **看 4 个关键信息**:
   - 接口描述
   - 输入参数表(必填/可选)
   - 输出参数表(返回字段)
   - **限制说明**(单次 max limit,是否支持 offset)
5. **把 URL 写进代码注释** + 把字段映射写进 `settings.py` 的 `CREATE TABLE`

**AI 接手时直接看注释里 URL**,不用再搜一遍。

### 步骤 3:`offline_db_client.py` 加 `get_xxx` 只读接口

**文件**:`scripts/core/offline_db_client.py`

**位置**:在文件末尾加新函数(跟 14 个 `get_*` 排在一起)。

**模板**(以不复权日 K 为例,跟 `get_day` 同结构):

```python
def get_hk_day(
    ts_code: Optional[str] = None,
    ts_codes: Optional[Iterable[str]] = None,
    start_date: Optional[Union[str, datetime]] = None,
    end_date: Optional[Union[str, datetime]] = None,
    trade_date: Optional[Union[str, datetime]] = None,
    columns: Optional[List[str]] = None,
    conn: Optional[sqlite3.Connection] = None,
) -> pd.DataFrame:
    """读港股日 K(未复权原始数据)

    数据源:db_cn_basic.db / tbl_hk_day
    主键:(ts_code, trade_date)
    字段(11):同 tbl_cn_day

    过滤条件(全部可选,默认 None = 不过滤):
      - ts_code: 单只港股,例 "00700.HK"
      - ts_codes: 多只港股
      - start_date: 起始日期(包含),YYYYMMDD / YYYY-MM-DD / YYYY/MM/DD
      - end_date: 结束日期(包含),同上
      - trade_date: 精确查某一天;传了就忽略 start/end_date
      - columns: 自定义返回列
      - conn: 可选外部 sqlite3 连接

    Returns:
        pd.DataFrame,按 (ts_code, trade_date) 升序;空表返回空 DataFrame
    """
    HK_DAY_TABLE = "tbl_hk_day"
    own_conn = conn is None
    if own_conn:
        conn = get_conn("basic")
    try:
        all_cols = ["ts_code", "trade_date", "open", "high", "low", "close",
                    "pre_close", "change", "pct_chg", "vol", "amount"]
        if columns is None:
            select_cols = all_cols
        else:
            bad = [c for c in columns if c not in all_cols]
            if bad:
                raise ValueError(f"非法列名: {bad};允许: {all_cols}")
            select_cols = columns

        wheres = []
        params: list = []

        if ts_code is not None and ts_codes is not None:
            raise ValueError("ts_code 和 ts_codes 互斥,只能传一个")

        if ts_code is not None:
            wheres.append("ts_code = ?")
            params.append(ts_code)
        elif ts_codes is not None:
            codes = list(ts_codes)
            if not codes:
                return pd.DataFrame(columns=select_cols)
            placeholders = ",".join(["?"] * len(codes))
            wheres.append(f"ts_code IN ({placeholders})")
            params.extend(codes)

        if trade_date is not None:
            td = _norm_date_yyyymmdd(trade_date)
            if td:
                wheres.append("trade_date = ?")
                params.append(td)
        else:
            sd = _norm_date_yyyymmdd(start_date)
            ed = _norm_date_yyyymmdd(end_date)
            if sd:
                wheres.append("trade_date >= ?")
                params.append(sd)
            if ed:
                wheres.append("trade_date <= ?")
                params.append(ed)

        where_sql = (" WHERE " + " AND ".join(wheres)) if wheres else ""
        sql = f"SELECT {','.join(select_cols)} FROM {HK_DAY_TABLE}{where_sql} ORDER BY ts_code, trade_date"
        df = pd.read_sql_query(sql, conn, params=params)
        if df is None or len(df) == 0:
            return pd.DataFrame(columns=select_cols)
        for col in select_cols:
            if col not in df.columns:
                df[col] = None
        df = df[select_cols]
        return df
    finally:
        if own_conn:
            conn.close()
```

## 4. 决策树:加新数据时遇到的具体选择

### 4.1 放哪个 DB?

```
新数据主题是 A 股 / K 线 / 复权 / 交易日历 / 股票基本信息?
  └─ 是 → db_cn_basic.db
新数据是开盘啦涨停 / 题材 / 涨停表现?
  └─ 是 → db_cn_kpl.db
新数据是新闻 / 联播?
  └─ 是 → db_cn_news.db
其他独立主题?
  └─ 新建独立 DB(db_cn_xxx.db,加 SCHEMA_SQL_XXX + DB_PATH_XXX)
```

### 4.2 跟哪个 update_* 模式?

```
新数据是按日循环的行情数据(单日 LIMIT 可能 > 1)?
  └─ update_daily / update_adj_factor / update_hk_day 模式
    - OFFSET 分页
    - 单日 LIMIT (6000 / 8000)
    - 50 页安全上限
新数据是单次整体拉取(不分日)?
  └─ update_major_news 模式(无日期循环,单次 pro.major_news(start, end))
新数据是按特定接口轮询?
  └─ 自定义模式
新数据是全量表(无日期维度)?
  └─ update_basic 模式(无日期循环,concat + 去重 + upsert)
```

### 4.3 走 service 还是直接 update_*?

```
新数据调度频率 = 完整更新链路的一部分(每天 1-3 次)?
  └─ 走 service(放 task_full_update 某阶段)
新数据有独立的调度需求(每天多次 / 实时)?
  └─ 走 service + 单独 task
新数据只是偶尔手动触发?
  └─ 不需要 service,直接 `down.update_xxx()` 调用即可
```

### 4.4 复用 get_* 还是新建?

```
新数据跟已有数据**字段相同**,只是表不同(港股日 K vs A 股日 K)?
  └─ 复用 get_day 模板(改表名 + conn),不要新建 get_xxx
新数据字段不同但查询模式类似(单日 / 区间 / 多股)?
  └─ 复制 _get_freq 模板新建
新数据查询模式完全不同?
  └─ 完全独立函数
```

## 6. 常见错误

### 6.1 忘了加 schema
**症状**:跑 service 报 `sqlite3.OperationalError: no such table: tbl_xxx`
**修法**:在 `settings.py` 加 `CREATE TABLE IF NOT EXISTS`,跑一次 `init_db` 自动建

### 6.2 ctrl key 写错
**症状**:增量更新退化成全量重拉(每次从 20150101 拉)
**修法**:在 `service_xxx.py` 跟 `update_xxx` 里**用同一个 `CTRL_KEY` 字符串**

### 6.3 文档同步漏了
**症状**:文档说"14 个 get_*"但实际是 15 个,新 AI 接手时按文档数计数
**修法**:严格按第 3 节"完整同步文档清单"逐个检查

### 6.4 service 顺序写错
**症状**:A 服务依赖 B 服务的数据但 B 还没跑
**修法**:在 `task_full_update` 4 阶段里挑对阶段;参考 `service_week` 的 `check_daily_adj_consistency` 校验

### 6.5 主键冲突导致 INSERT 失败
**症状**:upsert_df 返回 0 但实际有数据
**修法**:`upsert_df` 用 `INSERT OR IGNORE`,主键冲突跳过 — 不会失败。但**主键必须正确定义**(复合主键 / 主键字段名要跟 `key_cols` 完全一致)

### 6.6 把 4 阶段 / 3 个 task 概念搞混
**症状**:新 AI 写文档时说"加 1 个 task"但实际只改了 1 个阶段
**修法**:`task_full_update` 是**1 个 task**,内部跑**4 阶段**;`task_news_update` / `task_kpl_limit_performance` 是另外 2 个 task。**总共 3 个 task**,加新 service 默认放 `task_full_update` 4 阶段里

#### 8.6.2 实际接入(top_list + top_inst + suspend)

| 接口 | 循环策略 | 估算耗时 | 实际耗时 | 写入 DB |
|---|---|---|---|---|

- **循环策略 3 选 1**:
  - 按日(必填 trade_date 时):1400 次调用,~30 分钟
  - 按月(范围参数有效时):503 次调用,~5 分钟(快 6 倍)

- **表放哪个 DB 要先想清楚**:用户说"都放 kpl"但 tbl_cn_suspend 是单只级别(跟 stk_limit 同类),实际放回 basic 更合理(本案例就这样做)
- **后台跑 + notify**:`background=true` + `notify=true` 跑长任务,完成后会有通知

#### 8.6.4 补 3 个接口(block_trade / ggt_daily / hsgt_top10)

跟 8.6.2 同批做,但用户说"先做 top_list 和 top_inst"分开了。
