# Major News 新闻图数据库工具

本工具把 `tbl_major_news` 的每日事实新闻加工为可追溯的关系图，并把当日分析投影到独立 Obsidian Vault。事实源是 `offlineDataManager/data/db_cn_news.db` 的 `tbl_major_news`；关系库是 `offlineDataManager/data/db_major_news_events.duckdb`；可读投影是 `~/Documents/每日新闻分析/每日新闻/YYYY-MM-DD.md`。DuckDB 和 Obsidian 都可由原始库及每日中间产物重建。当前每日分析只处理 **Major News**，普通快讯与 CCTV 仍留在原始库，不混入本工具的分母。

## 数据链与图结构

`tbl_major_news` → `rel_news_event_member` / `fact_news_event`（规则去重、结果稿过滤）→ `rel_major_news_semantic_member` / `fact_major_news_semantic_event`（跨源语义聚类）→ `fact_major_news_analysis`（Qwen 入选、重要性、利好/利空/中性、依据、部分深度提炼）→ `rel_major_news_theme`、`rel_major_news_entity`（题材和实体候选边）→ `fact_major_news_daily_analysis` → Obsidian。

| 表 | 粒度与用途 |
|---|---|
| `fact_news_event`、`rel_news_event_member` | 规则事件，以及每条原始新闻到规则事件的成员关系；排除项仍保留供审计。 |
| `fact_major_news_semantic_event`、`rel_major_news_semantic_member` | 语义事件及其规则事件成员；保存原始报道数、来源数、首末发布时间和当日代表文本快照，后续报道不能覆盖历史文本。 |
| `fact_major_news_analysis` | 每条入选事件一行。所有入选事件均有方向评级和简短依据；最高分事件另有摘要、事实、题材、实体和影响周期。记录模型、提示词哈希、输入哈希、未复核状态。 |
| `dim_major_news_theme_tag`、`rel_major_news_theme` | 模型给出的题材原始标签与 `related_to` 候选边。仅在新闻日期已存在且名称/别名唯一匹配时引用 KPL `theme_id`；未匹配或歧义标签保留原文，不伪造身份。ST、次新标签排除。 |
| `dim_major_news_entity`、`rel_major_news_entity` | 模型提取的实体与事件候选边。实体名称只是文本身份，尚未对接上市公司主数据。 |
| `fact_major_news_daily_analysis` | 每日语义事件、入选、深提炼、三类评级数量与产物哈希。 |

这里的“图数据库”是 DuckDB 内的节点表和带时间、证据状态的关系表，适合按日期和题材快速筛选，并不依赖独立的图数据库服务。模型的 `related_to` 表示**新闻涉及该题材**，不是已证实的炒作原因，更不能直接回写 KPL 题材事实库。要确认催化因果，仍需原始新闻全文、发布时间与题材周期证据审计。规则事件可能持续接收后续报道，因此语义聚类使用截至分析日的成员与代表文本快照。盘中历史查询不能直接把当日盘后聚类或模型结论当作盘中已知信息；该库当前按**自然日盘后截止**使用。

## 新增、补录、查询

从仓库根目录运行，使用项目 `.venv`：

```bash
# 处理一个已有 Major News 日期：增量清洗、语义聚类、模型提炼、写图、写 Obsidian
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool update --date 20260924

# 按原始库有新闻的自然日回填；每日期缓存可续跑
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool backfill --start-date 20260901 --end-date 20260924

# 大范围回填可用两阶段流水线：次日清洗/向量化与当日 Qwen 提炼重叠
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.pipeline_major_news_backfill --start-date 20260101 --end-date 20260927

# 先核对/补抓原始 Major News 缺失日；Mac mini 已配置 Tushare token
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.backfill_major_news_gaps --start-date 20260101 --end-date 20260927 --dry-run
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.backfill_major_news_gaps --start-date 20260101 --end-date 20260927 \
  --ssh-host macmini

# 已有日期也可能只抓到半天；逐日分页复核并可续跑
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.backfill_major_news_gaps --start-date 20260101 --end-date 20260927 \
  --ssh-host macmini --refresh-existing

# 仅把已完成的模型产物重新导入图库，适合数据库重建后补录
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool import --date 20260924

# 按日期、方向、题材及重要性查询正式归档；也支持 --keyword、--theme-label、--entity
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool query --start-date 20260924 --end-date 20260924 \
  --impact bullish --min-importance 60 --limit 20

# 查单条事件的原始报道、规则成员、题材及实体关系
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool event --id SE-具体事件ID --as-of 20260924

# 日度入库数量与评级分布、从数据库重建文档
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool status --start-date 20260901 --end-date 20260924
PYTHONPATH=offlineDataManager/scripts:. .venv/bin/python \
  -m service.news_graph_tool project --date 20260924
```

`update`（别名 `add`）是新增一日数据的标准入口；原始新闻的日常抓取继续由 `service_major_news.py` 负责。`backfill_major_news_gaps.py` 默认补抓完全空白的日期，`--refresh-existing` 复核已有日期并补入遗漏报道；两者都按页请求 Tushare、写入原始 SQLite，不改写日常增量断点；`--ssh-host macmini` 让 token 留在 Mac mini，新闻数据经 SSH 返回本机。空结果或达到分页上限的日期保留为失败，不能假装已补齐。`backfill` 逐日运行模型分析，按原始新闻数量、数据库统计和 Obsidian 文档验收；默认跳过已验证日期，进度写入 `outputs/major_news_analysis/backfill_status_<起日>_<止日>.json`，单日失败可续跑，连续失败三天则暂停以便排查。`import` 不发起模型调用，只导入 `outputs/major_news_analysis/YYYYMMDD/` 已有完整产物。重跑同一日期在事务里替换该日图数据，不累加重复边。`project` 从正式 DuckDB 读取分析，重建该日 Markdown；Obsidian 页面不是模型数据的唯一保存处。`--force` 会重算向量和模型批次，耗时与模型服务有关。

已有日期可能只抓到部分新闻，所以 `--refresh-existing` 也要用于源库完整性审计。它按自然日重新分页抓取，用现有主键去重补入遗漏报道；状态记录在 `outputs/major_news_analysis/source_full_refresh_<起日>_<止日>.json`，再次运行会跳过已完成日期。若原始新闻条数增加，模型分析批次会重算相应日期，并更新图数据库与 Obsidian。

长批次可由 `service.run_major_news_after_source_refresh` 接力：它等待源数据状态为 `complete`，核对指定范围每个自然日的抓取状态和 SQLite 条数，然后启动 `service.news_graph_tool backfill`。接力状态保存在 `outputs/major_news_analysis/backfill_supervisor_<起日>_<止日>.json`；源数据验收失败时不会启动模型。Tushare 返回的重复主键会被 SQLite 去重，所以逐日验收比较去重后的入库计数，而不是原始返回行数。

`pipeline_major_news_backfill` 只同时运行一日 Qwen 提炼和下一日的规则清洗/向量聚类；规则库写入及正式图库/Obsidian 发布串行，保留跨日去重顺序，也不超过模型服务配置的 4 路请求并发。它复用已有单日缓存、正式数据库验收和 `backfill_status_<起日>_<止日>.json`，再次运行会跳过已验收日。不要与普通 `backfill` 同时运行同一日期范围。

业务代码通过统一接口读取：

```python
from coreClient.data_provider import (
    get_major_news_analysis,
    get_major_news_theme_edges,
    get_major_news_daily_summary,
    get_major_news_event_graph,
)

analysis = get_major_news_analysis("20260924", "20260924", market_impact="bullish", min_importance=60)
theme_edges = get_major_news_theme_edges("20260924", "20260924")
daily = get_major_news_daily_summary("20260924", "20260924")
graph = get_major_news_event_graph("SE-具体事件ID", as_of="20260924")
```

`get_major_news_analysis(..., theme_id=...)` 只命中历史当日唯一匹配的 KPL 题材 ID。需要查看未匹配标签时读 `get_major_news_theme_edges`，核对 `match_status` 与 `evidence_status`。原始报道仍可用既有 `get_major_news()` 查询。

## 日常验收

每个日期独立核对四件事：原始库该日新闻数量、规则事件与排除数、图库 `selected_events` 与三类评级之和是否一致、Obsidian 当日文档是否实际写入且数字一致。抽查 `get_major_news_event_graph` 是否能返回原始报道。模型标签的 `matched` 只是身份映射，不等于因果复核；将来做题材催化证据时需单独审核来源和时间。新数据到来后可重新运行当日 `update`，最终以当日 `artifact_hash` 和数据库统计确认版本。

运行入口见 `offlineDataManager/scripts/service/news_graph_tool.py`，表结构和导入逻辑见 `offlineDataManager/scripts/core/major_news_graph_store.py`，Obsidian 渲染见 `offlineDataManager/scripts/service/project_daily_news_to_obsidian.py`。上游去重、过滤、模型级联细节见 [新闻清洗压缩与LLM提炼工具.md](新闻清洗压缩与LLM提炼工具.md)。
