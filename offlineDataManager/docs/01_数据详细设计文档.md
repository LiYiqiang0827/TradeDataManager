# 01 数据详细设计文档

> 本文是 4 个 SQLite 库 + 31 张表的**唯一 schema 文档**(含 4 个 ctrl 断点表 + 27 张数据表)。每个表包含:字段语义、类型、主键、索引、来源、写入者、读取者。
> 数据规模为 2026-09-15 实测。

## 2. db_cn_basic.db (3.6 GB, 14 表)

### 2.1 `tbl_cn_basic` — 股票基本信息(全量)

| 项 | 值 |
|---|---|
| 主键 | `ts_code` |
| 写入者 | `CNDataDown.update_basic()` |
| 读取者 | `get_basic()` |
| 数据源 | tushare `pro.stock_basic`(list_status=L+P,**不含 D 退市**) |
| 数据行数 | 5,562 |

**字段(15)**:

| 字段 | 类型 | 语义 |
|---|---|---|
| `ts_code` | TEXT PK | 股票代码,带后缀(.SH/.SZ/.BJ) |
| `symbol` | TEXT | 纯数字代码,如 `000001` |
| `name` | TEXT | 简称,如 `平安银行` |
| `industry` | TEXT | 所属行业(申万),**可读但 `get_basic` 不支持 industry 过滤** |
| `fullname` | TEXT | 公司全称 |
| `enname` | TEXT | 英文名 |
| `cnspell` | TEXT | 中文拼音缩写 |
| `market` | TEXT | 板块:`主板` / `创业板` / `科创板` / `北交所`(对应关系见下表) |
| `exchange` | TEXT | 交易所:`SSE` / `SZSE` / `BSE` |
| `curr_type` | TEXT | 币种,基本都是 `CNY` |
| `list_status` | TEXT | `L` 上市 / `P` 暂停 / `D` 退市(DB 只存 L+P) |
| `list_date` | TEXT | 上市日期 YYYYMMDD(字符串排序 == 时间排序,可直接用 `WHERE list_date >= '20240101'`)|
| `delist_date` | TEXT | 退市日期 YYYYMMDD(D 状态有) |
| `is_hs` | TEXT | 沪深港通标记 `N` / `H` / `S`(H 沪股通 / S 深股通) |
| `snap_ts` | TEXT | 写入时间 ISO 格式 |

**索引**:主键 ts_code,无其他索引(全表才 5 千行,过滤靠内存)

**重要约束**:
- `exchange` (SSE/SZSE/BSE) 和 `market` (主板/创业板/科创板/北交所) **不是任意组合**:
  - SSE = 主板(部分)+ 科创板
  - SZSE = 主板(部分)+ 创业板
  - BSE = 北交所
  - 即:"沪市主板+科创板=整个沪市","深市主板+创业板=整个深市"
- 写 SQL 过滤时,这个对应关系由数据本身保证(`update_basic` 从 tushare 拉的就是合法的)
- `industry` 字段是 15 列之一,但 **`get_basic` 不支持 industry 过滤**(代码只有 exchange/market/list_status 三个过滤参数)。需要按行业过滤时自己写 SQL 或在 pandas 里 `df[df.industry == '银行']`

**写入规则**:
- `update_basic(bFull=False)` 调 tushare 拉 L + P 两个状态,concat + 去重 + upsert
- `bFull=True` 时 `DELETE FROM tbl_cn_basic` 后整体 upsert(谨慎使用,会清掉 P 状态的本地更新)
- 断点:`tbl_basic_ctrl.cn_basic = snap_ts()`(snap_ts 不是日期,只是"这次拉过"的标记,**因为 `tbl_cn_basic` 是全量表,无日期维度,所以"上次拉过"用时间戳记录,不是用日期推进**)
- **历史差异**:`cn_basic` 用 ISO datetime,其他 7 个 key 都用 YYYYMMDD。原因是 basic 是一次性全量拉取,不分日;其他表按日期循环,有自然日期维度

### 2.2 `tbl_cn_tradecal` — 交易日历

| 项 | 值 |
|---|---|
| 主键 | `(cal_date, exchange)` 复合主键 |
| 写入者 | `CNDataDown.update_tradecal()` |
| 读取者 | `get_tradecal()` |

| 数据行数 | 6,358(2018-01-01 起,3 个交易所) |
| 起始日期 | 20180101 |

**字段(5)**:

| 字段 | 类型 | 语义 |
|---|---|---|
| `cal_date` | TEXT PK | 日历日 YYYYMMDD |
| `exchange` | TEXT PK | `SSE` / `SZSE` / `BSE` |
| `is_open` | INTEGER | 1=开市 / 0=休市 |
| `pretrade_date` | TEXT | 上一交易日 YYYYMMDD(开市日才有) |

- 全量:从 20180101 开始
- BSE 实际从未拉到数据(DB 里只有 SSE + SZSE),2026-09-15 修复版未清理历史空行

### 2.2.5 `tbl_cn_stk_limit` — 每日涨跌停价格(2026-09-15 新增)

| 项 | 值 |
|---|---|
| 主键 | `(trade_date, ts_code)` 复合主键 |
| 写入者 | `CNDataDown.update_stk_limit()` |
| 读取者 | `get_stk_limit()` |
| 数据源 | tushare `pro.stk_limit`(文档 https://tushare.pro/document/2?doc_id=183) |
| 限制 | 单次最多 5800 条(A 股全市场 ~5438 条/日,不用分页) |
| 起始日期 | 默认 20150101 |

**字段(5)**:

| 字段 | 类型 | 语义 |
|---|---|---|
| `trade_date` | TEXT PK | 交易日 YYYYMMDD |
| `ts_code` | TEXT PK | 股票 / 场内基金代码 |
| `up_limit` | REAL | 涨停价 |
| `down_limit` | REAL | 跌停价 |
| `snap_ts` | TEXT | 写入时间 |

**索引**:
- PK: `(trade_date, ts_code)`
- `idx_stk_limit_date` ON `(trade_date)`(按日期查全市场用)

**写入规则**:
- 按日循环(实测 tushare `start_date + end_date` 范围参数不生效,只能 `trade_date` 单日拉)
- 单日全市场 ~5438 行,无分页
- 断点:`tbl_basic_ctrl.cn_stk_limit`
- 空日不推进断点(节假日)

**特殊说明**:
- tushare `pro.stk_limit` 的 `start_date` / `end_date` 范围参数**实测不生效**,只能 `trade_date` 单日拉
- 包含 A 股 + 场内基金(ETF/LOF),**不区分**,都存进同一张表

**性能**(实测 2026-09-15):
- 单日拉取 0.2s,写 5438 行
- 全量 2 年(503 个交易日):**3.5 分钟**,**+262 万行**
- 限流偶尔触发(Tushare 200/分钟),`RateLimiter` 自动 sleep 17s

- S(停牌)271,096 行(96.2%)+ R(复牌)10,662 行(3.8%)
- 唯一 ts_code 4,401 只

- `tbl_cn_day` 存的是 tushare 返回的原始 OHLCV,**不存前复权**
- 前复权在 `get_day(qfq=True)` 读时 join `tbl_cn_adj_factor` 计算:
  ```
  qfq_factor = adj_factor[当天] / adj_factor[最新]
  open_qfq  = open  * qfq_factor
  close_qfq = close * qfq_factor
  vol_qfq   = vol   / qfq_factor
  amount 不变(成交额不受复权影响)
  ```
- 好处:原始数据可追溯,任意时刻都能根据 adj_factor 重算

**写入规则**:

- **注意**:`update_cctv_news` **不显式算 md5 字段**,df 里没 md5 列,upsert 时只插 datetime/title/content/src/snap_ts。SQLite 主键检查时 md5 字段为 NULL,实际主键约束退化成只按 datetime 判重(由 `service_cctv_news` 按日期循环的调度保证不重)

## 6. 数据完整性约束

- **主键去重**:`upsert_df(conn, df, table, key_cols=...)` 用 `INSERT OR IGNORE`,主键冲突行跳过(等价幂等)
- **多日表**:week / month 用 `replace_table`(DELETE + INSERT 事务化),`last_success_date` 只在有 INSERT 时推进
- **断点推进**:每张表的断点只在实际写入成功后更新(`if inserted > 0: update_ctrl`)
- **空日不推进**:`update_kpl_list` / `update_kpl_limit_performance` / `update_daily` 等循环里,空日(`df is None or len(df) == 0`)`continue` 但**不更新断点**
